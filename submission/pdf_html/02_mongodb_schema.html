Collection Schemas

users

One document per registered user. Passwords are BCrypt-hashed and never returned by any API endpoint.

{
  "_id":       "ObjectId",
  "email":     "admin@hrms.com",
  "password":  "$2a$10$...",      // BCrypt hash — never exposed
  "role":      "ADMIN",
  "createdAt": "2026-09-03T01:50:00",
  "updatedAt": "2026-09-03T01:50:00"
}
FieldTypeRequiredNotes
_idObjectIdAutoMongoDB default primary key
emailStringYesUnique. Lookup is case-insensitive at login.
passwordStringYesBCrypt-hashed. Never returned by API.
roleEnumYesADMIN | EMPLOYEE | HR
createdAtDateTimeAutoSet on registration
updatedAtDateTimeAutoUpdated on every change

  "salary":        80000,

  "deductions":    5000,

  "createdAt":     "2026-09-03T10:00:00",

departments

One document per department. Every department must have a dedicated HR employee assigned.

{
  "_id":          "ObjectId",
  "departmentId": "DEPT-0001",
  "name":         "Engineering",
  "description":  "Software development team",
  "managerId":    "EMP-0002",   // optional
  "hrId":         "EMP-0003",   // required — one HR per dept
  "isSystem":     false,
  "createdAt":    "2026-09-03T11:00:00",
  "updatedAt":    "2026-09-03T11:00:00"
}
FieldTypeRequiredNotes
departmentIdStringAutoSequential: DEPT-0001, DEPT-0002, …
nameStringYesUnique department name
descriptionStringNo
managerIdStringNoReferences employees.employeeId. Must be MANAGER type.
hrIdStringYesReferences employees.employeeId. Must be HR role. One HR per department only — uniqueness enforced at service layer.
isSystemBooleanAutotrue only for DEPT-0000 (Unassigned). System departments cannot be deleted.
Auto-seeded system department: DEPT-0000 "Unassigned" — a holding bucket for employees without a department. Created automatically on first startup.

leave_requests

One document per leave application submitted by an employee.

{
  "_id":        "ObjectId",
  "leaveId":    "LVE-0001",
  "employeeId": "EMP-0001",
  "leaveType":  "ANNUAL",
  "startDate":  "2026-10-01",
  "endDate":    "2026-10-05",
  "totalDays":  5,
  "reason":     "Family vacation",
  "status":     "PENDING",
  "appliedAt":  "2026-09-15T09:00:00",
  "updatedAt":  "2026-09-15T09:00:00"
}
FieldTypeNotes
leaveIdStringSequential: LVE-0001, LVE-0002, …
employeeIdStringReferences employees.employeeId
leaveTypeEnumANNUAL | CASUAL | SICK | UNPAID
startDateDateMust not be after endDate
endDateDate
totalDaysNumberAuto-calculated: endDate − startDate + 1
reasonString
statusEnumPENDING → APPROVED or REJECTED. Only PENDING requests can be actioned by HR.

leave_balances

One document per employee. Auto-created with default values when an employee profile is registered.

{
  "_id":          "ObjectId",
  "employeeId":   "EMP-0001",
  "annualLeaves": 18,
  "casualLeaves": 10,
  "sickLeaves":   8,
  "unpaidLeaves": 5,
  "updatedAt":    "2026-09-03T10:00:00"
}

Each quota field is automatically decremented when a leave request of that type is approved. If the balance is insufficient, the approval is rejected with a validation error.

payroll

One document per employee per month/year. Duplicate payroll for the same employee + month + year is not allowed.

{
  "_id":           "ObjectId",
  "payrollId":     "PAY-0001",
  "employeeId":    "EMP-0001",
  "month":         9,
  "year":          2026,
  "basicSalary":   80000,
  "allowances":    10000,
  "deductions":    5000,
  "netSalary":     85000,     // basicSalary + allowances − deductions
  "paymentStatus": "UNPAID",
  "generatedAt":   "2026-09-30T18:00:00",
  "updatedAt":     "2026-09-30T18:00:00"
}
FieldNotes
basicSalaryCopied from employees.salary at generation time
allowancesCopied from employees.allowances
deductionsCopied from employees.deductions
netSalaryAuto-calculated: basicSalary + allowances − deductions
paymentStatusStarts as UNPAID. HR marks it PAID.

employee_history

Immutable audit log. Records are never deleted — they capture every significant event in an employee's career.

{
  "_id":            "ObjectId",
  "employeeId":     "EMP-0001",
  "type":           "PROMOTION",
  "previousValue":  "EMPLOYEE",
  "newValue":       "MANAGER",
  "note":           "Promoted to Manager role",
  "recordedAt":     "2026-09-10T14:30:00"
}
TriggerTypePrevious / New value
Admin changes employee typePROMOTIONOld type → New type (e.g. EMPLOYEE → MANAGER)
Admin changes designation via profile updateDESIGNATION_CHANGEOld designation → New designation
Admin adds a performance notePERFORMANCE_NOTENote text stored in note field

Entity Relationships

users ──────────────────────────── employees
(email links the two)              (employeeId)
                                        │
                          ┌─────────────┼────────────────────┐
                          │             │                    │
                     departments   leave_requests        payroll
                     (managerId,   (employeeId)       (employeeId)
                      hrId →
                      employees)        │                    │
                                  leave_balances     employee_history
                                  (employeeId)        (employeeId)
MongoDB does not enforce foreign key constraints. Referential integrity is maintained at the application (service) layer. For example, the service validates that a department's hrId references an existing HR-type employee before saving.
